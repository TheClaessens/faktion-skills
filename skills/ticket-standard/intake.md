# Reading a brain-dump

How requesters actually deliver work: conversational, often spoken, frequently self-correcting. Read this when the input is a ramble rather than a written spec.

- **Let the thought finish before drafting.** Interrupting to draft loses the correction that was coming.
- **Take the correction, not the original.** "No wait, actually..." and "let me rephrase" overwrite what came before.
- **Separate context from requirement.** Background explaining *why* they want it helps you understand and stays out of the ticket. Extract the requirement it wraps.
- **Preserve the specific names they reached for.** An API name, a table, a named existing implementation - these are load-bearing and go in verbatim.
- **Ask when genuinely unsure whether something is in scope.** Use the conversation to close ordinary gaps; save the question for the ones that change the ticket.
